3關聯處理(Contact → Account)

依 docx §6.1:聯絡人 AccountId 對應客戶管理的 Id。來源 AccountId 有兩種型態,對應規則如原始公式:

  • 純數字型 AccountId → 比對 Account 的 IDNo(即 Legacy_IDNo__c)
  • SF 格式(001…)AccountId → 比對 Account 的舊 Id(即 Legacy_Id__c)

本地讀取已匯入的 4,334 筆 Account 對應表(Id | Legacy_Id | Legacy_IDNo),先解析成真實 18 碼 Account Id 再寫入 Contact.AccountId,避免 Bulk API 單鍵關聯遇數字/SF 混用時錯掛。

4資料清洗

每個欄位在寫入前皆套用基礎 ETL 清洗:

  • 首尾空白 trim — 半形空白與全形空格(U+3000)一併處理
  • 連續空白收斂 — 多個空白合併為單一半形空白
  • 去不可見字元 — 移除 \t、\r、零寬字元等控制字元
  • 國別標準化 — MailingCountry 含「台/臺/灣」統一為「臺灣」
  • 稱呼標準化 — 先生→Mr.、小姐→Ms.
  • 日期轉型 — Excel 序號 → Birthdate(YYYY-MM-DD)、Legacy_Created_Date__c(ISO DateTime)
  • 金額轉型 — 先去除逗號/貨幣符號再轉數值
完全重複列檢查:以全 41 欄清洗後內容做 hash 比對,0 筆完全相同的重複列 → 無需去重。長度溢位檢查:0 筆超過欄位上限。
