05匯入批次過程

使用 Bulk API 2.0 upsert,以 External ID 為 key 確保可重跑不重複。

試批驗證(5 筆)
先匯 5 筆確認中文、日期、picklist、正規化皆正確落地,才進行全量。
第一批(4,153 筆)
以 Legacy_Id__c 為 key 匯入 → 4,153 成功;181 筆因來源無 Id 而 MISSING_ARGUMENT 失敗。
診斷
失敗 181 筆為純 BA 系統資料:僅有 IDNo、無 Salesforce Id,故無法用 Legacy_Id__c 當 key。
補匯(181 筆)
改以 Legacy_IDNo__c 為 key 匯入該子集 → 181 成功、0 失敗。
最終驗證
SOQL 核對:mark='sf' 共 4,334 筆,與來源一致。
指令範例:
sf data upsert bulk --sobject Account --external-id Legacy_IDNo__c --file accounts.csv --line-ending LF --target-org lifenergy

07陷阱與關鍵決策

決策 ① AccountSource 改存 custom 文字欄
本 org 的標準值集 AccountSource 無法透過 Metadata API 新增中文值(retrieve/deploy 皆被拒)。為不遺失來源資料,原始值先存入 Account_Source_Text__c(403 筆有值)。如需轉為原生 picklist 選項,須於 Setup UI 手動加值,可另行提供清單。
決策 ② 181 筆無 Id 資料改用 IDNo 補匯
來源 181 筆為純 BA 系統資料,只有 IDNo、無 Salesforce Id。以 Legacy_IDNo__c 為 key 分批 upsert 補齊,確保全量到位且可重跑不重複。
  • custom field API name 須 ASCII — 一律用英文 API 名 + 中文 Label。
  • FLS 陷阱 — 新 custom 欄位 admin 不會自動有 FLS,靠 permission set 集中授權(見下節)。
  • git-bash 相容 — sf data query 有 'C:\Program' bug,查詢改走 sf apex run。

08權限指派(FLS)

15 個 custom 欄位的 FLS 由 permission set Lebio Import Fields(Lebio_Import_Fields)集中管理,並依「權限開給所有 User,客戶才看得到」原則,指派給所有相容 license 的 active User。
