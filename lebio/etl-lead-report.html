4資料清洗

來源合併自 SF 匯出(6,600)與 BA 系統(1,345),每個欄位在寫入前皆套用基礎 ETL 清洗:

  • 首尾空白 trim — 半形空白與全形空格(U+3000)一併處理
  • 連續空白收斂 — 多個空白合併為單一半形空白
  • 去不可見字元 — 移除 \t、\r、零寬字元等控制字元
  • 國別標準化 — Country 含「台/臺/灣」統一為「臺灣」
  • Company 必填補值 — 來源公司為空時以聯絡人姓名補入(7,540 筆),避免必填擋批
  • Email 格式驗證 — 以 /^[^\s@]+@[^\s@]+\.[^\s@]+$/ 驗證;不合格者(1 筆:地址誤植於 Email 欄)移入 Street、Email 清空,不丟失資料
  • 日期轉型 — Excel 序號 → Legacy_Created_Date__c(ISO DateTime)
完全重複列檢查:以全欄清洗後內容做 hash 比對,合併兩來源後0 筆完全相同的重複列 → 無需去重。長度溢位檢查:欄位一律 cut 至上限(Street 255 / Email 80),0 筆因溢位失敗。

6匯入執行與例外處理

部署 metadata — 19 個自訂欄位 + permission set Lebio_Import_Lead,一次部署成功。
全量 7,945 筆 — Bulk API 2.0 upsert(key = Legacy_IDNo__c)。首輪 7,935 成功,10 筆被攔截:9 筆 DUPLICATES_DETECTED、1 筆 INVALID_EMAIL_ADDRESS。
例外 1 筆(無效 Email) — IDNo 8213「大灣藥局」來源將地址誤植於 Email 欄。清洗規則將該值移入 Street、Email 清空後重新匯入,成功。
例外 9 筆(重複規則) — 皆為已轉換商機,其 Account/Contact 已存在,觸發 Standard_Lead_Duplicate_Rule 的跨物件比對(Block)。DuplicateRuleHeader.allowSave 無法略過此 Block 行為。
安全略過重複規則 — 暫時停用 Standard_Lead_Duplicate_Rule(isActive=false)→ 全量重新 upsert → 立即還原啟用(isActive=true),確保正式 org 規則狀態不變。9/9 補入。
最終結果 — 7,945 / 7,945 = 100% 匯入完成,重複規則已還原為 active。
正式 org 保護:停用重複規則僅在匯入當下短暫進行,匯入後第一時間還原,期間不影響一般使用者建立資料的規則保護。
